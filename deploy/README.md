# JARVIS на сервере, интерфейс на Mac

Мозг и интерфейс крутятся на сервере, браузер — на Mac. Связь через SSH-туннель.

## Почему именно туннель

Микрофон в браузере работает только в защищённом контексте: по `https://` либо
на `localhost`. Открыть `http://адрес-сервера:5173` недостаточно — страница
загрузится и будет выглядеть живой, но микрофон не включится, и это не
лечится настройками.

Туннель решает это бесплатно: браузер обращается к `localhost:5173`, а SSH
незаметно уводит трафик на сервер. Для браузера это localhost, значит
микрофон работает. Сертификаты не нужны, наружу на сервере ничего не открыто,
`JARVIS_ALLOWED_ORIGINS` и `vite --host` не нужны — allowlist моста уже
принимает `localhost:5173–5199`.

```
  Mac                                   сервер
  Chrome → localhost:5173 ──┐
                            │ ssh -L    ┌─ vite   :5173
                            ├──────────►│
  мост  → localhost:8787 ───┘           └─ bridge :8787 → claude
```

## Что нужно на сервере

- Node.js 20+
- Claude Code, установленный **и залогиненный** (`npm install -g @anthropic-ai/claude-code`, затем `claude` и вход в аккаунт)
- tmux — чтобы запуск жил после отключения
- доступ по SSH-ключу (`ssh-copy-id логин@адрес`)

Логин в Claude Code нужно сделать самому: это интерактивный вход в аккаунт.
`deploy.sh` проверит все четыре пункта и скажет, чего не хватает.

## Порядок

```bash
./deploy/deploy.sh логин@адрес            # проверки, клон, npm install
./deploy/run.sh    логин@адрес            # запуск в tmux (только чтение)
./deploy/tunnel.sh логин@адрес            # проброс портов, держать открытым
```

Затем в Chrome: <http://localhost:5173> → **INITIALISE** → «Hey Jarvis».

Чтобы разрешить действия — `./deploy/run.sh логин@адрес --writes`. На сервере
это значит, что JARVIS сможет выполнять команды и менять файлы **на сервере**,
а не на Mac.

## Если что-то не так

| Симптом | Причина |
|---|---|
| Туннель не поднимается, пишет про занятый порт | На Mac ещё работает локальный JARVIS — останови его |
| Страница есть, микрофон не просит доступ | Открыт не `localhost`, а адрес сервера — микрофон так не заработает |
| Интерфейс живой, но не отвечает | Мост не поднялся или не пробросился порт 8787: `ssh логин@адрес 'tail -f ~/jarvis.log'` |
| Мост пишет про логин | На сервере не выполнен вход: `ssh -t логин@адрес claude` |

Лог: `~/jarvis.log` на сервере. Сессия: `tmux attach -t jarvis` (выход — Ctrl-B, затем D).
